## 0. 这节课要解决什么

老师给的原话是：

> **其实也就是上一个案例中 user 后面 content 的内容**

翻译一下：**prompt（提示词）不是什么新东西，它就是你发给模型的那句话。**

上一节课的代码长这样：

```python
messages=[
    {"role": "system", "content": "你是一个耐心的 Python 助教"},   # 人设
    {"role": "user",   "content": "用一句话解释什么是大语言模型。"},  # ← 这里就是 prompt
]
```

这一节只是把它**先存到变量里**，再交给 `messages` 用，顺便讨论"怎么把这句话写好"：

```python
prompt = "我想学习人工智能相关技术，需要掌握哪些技能可以找到理想的工作？"
```

> 核心结论一句话：**模型是同一台引擎，prompt 就是方向盘。** 同一句话问得含糊或问得清楚，答案的质量差一个档次。

## 2. `messages` 里的三个角色（本节最容易搞混的点）

| role | 谁说的话 | 用途 | 例子 |
| --- | --- | --- | --- |
| `system` | 系统 / 开发者 | **设定人设、规则、边界** | "你是一名人工智能专家"、"只回答中文" |
| `user` | 用户（你） | 提问、下任务 | `prompt` 变量 |
| `assistant` | **模型自己** | 模型之前的回答（多轮对话时把历史塞回来） | 上一轮它说的话 |

### 老师用 `assistant` 放人设，能跑但有隐患

老师的写法：

```python
messages=[
    {"role": "assistant", "content": "你是一名人工智能专家"},   # ← 用人设占了一个"助手说过的话"
    {"role": "user", "content": prompt},
]
```

这段能正常出结果（本机实测通过，见第 4 节），因为模型会把它理解成"我之前已经这么说过自己了"。
但从语义上讲，**`assistant` 表示"模型说过的话"，`system` 才是"给模型下的规则"**。

**推荐写法：**

```python
messages=[
    {"role": "system", "content": "你是一名人工智能专家"},   # 规范：规则归 system
    {"role": "user", "content": prompt},
]
```

### 还有个顺序细节

`system` 应该放在**最前面**。`messages` 是**有顺序**的列表，模型按顺序读：

```
正确的顺序：  system（规则） → 历史对话（user/assistant 交替） → 最新的 user 提问
```

顺序颠倒或用 `assistant` 开头，都不会报错，但模型的理解可能跑偏 —— 这类问题**不报错、只是答得不对**，最难查。

## 3. 完整代码（`02.认识prompt提示词.py`）

```python
import os
import sys

# Windows 控制台默认 GBK，模型回复里若带 emoji（如 ⭐），print 会直接崩。
# 这一行让"打不出来的字符"自动变成 ?，而不是崩掉。
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(errors="replace")

from dotenv import load_dotenv
from openai import OpenAI

THINKING = "disabled"        # 思考模式开关（见 day01 笔记 5.5）
MODEL = "deepseek-flash"

load_dotenv(override=True)   # override=True：别让系统里同名的环境变量盖掉 .env

api_key = os.environ.get("DEEPSEEK_API_KEY")
if not api_key:
    raise SystemExit("没有读到 DEEPSEEK_API_KEY，请确认项目目录下有 .env 文件。")

client = OpenAI(api_key=api_key, base_url="https://api.deepseek.com")

# 编写提示词
prompt = "我想学习人工智能相关技术，需要掌握哪些技能可以找到理想的工作？"

# 与人设一起发给模型
res = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "你是一名人工智能专家"},
        {"role": "user", "content": prompt},
    ],
    extra_body={"thinking": {"type": THINKING}},
)

# 获取 AI 的回复，在控制台输出
print(res.choices[0].message.content)
```

运行：

```powershell
cd F:\项目文件夹\智能体\agent

```

## 4. 实测：人设放 `assistant` 还是 `system`？

本机 2026-10-12 用同一个 `prompt`、同一个模型跑了两次（`deepseek-flash`，思考模式关闭）：

| 写法 | 输入 tokens | 输出 tokens | 结果 |
| --- | --- | --- | --- |
| `assistant` 放人设（老师写法） | 26 | 1278 | 正常回答，篇幅更长、更"汇总型" |
| `system` 放人设（规范写法） | 24 | 1253 | 正常回答，分节更清楚、更像"讲给人听" |

**结论**：两种都能用，输出量也接近。但**规则就该写 `system`** —— 语义清楚，后面做多轮对话时才不会跟真正的历史回答混在一起。

> 顺便一个反直觉的点：`assistant` 写法输入反而**多 2 个 token**，因为"助手说过的话"在模板里比 `system` 多几个特殊标记。差异可以忽略，但足以说明"能跑"不等于"写对了"。

## 5. 怎么写一个好用的 prompt

### 5.1 一个够用的公式

```
角色 + 任务 + 要求/约束 + 输出格式 + 长度
```

对着第 3 节那个 `prompt` 套一下，就能看出它其实"只有任务，没有人设细节"：

| 要素 | 老师的 prompt | 补全后的写法 |
| --- | --- | --- |
| 角色 | （靠 `system` 里那句"你是一名人工智能专家"） | 你是 AI 行业的技术面试官 |
| 任务 | 需要掌握哪些技能可以找到理想的工作 | 为零基础转行的学生规划 6 个月学习路线 |
| 要求 | 无 | 分 3 阶段、每阶段 2-3 个技能、指出一个最容易踩的坑 |
| 格式 | 无 | 用 Markdown 小标题组织 |
| 长度 | 无 | 300 字以内 |

### 5.2 实测对比：模糊 prompt vs 结构化 prompt

| prompt | 输入 tokens | 输出 tokens | 输出效果 |
| --- | --- | --- | --- |
| `帮我讲讲AI` | 7 | 487 | 一口气讲了 AI 是什么、发展史、核心概念、能做什么……内容正确，但**面面俱到、没法直接用** |
| 结构化写法（角色+任务+要求+格式+字数） | 98 | 294 | 直接给出"阶段一/二/三"的路线，每个阶段带技能和踩坑提醒，**严格守在 300 字以内** |

**两个实用规律：**

1. **输入多花 91 个 token，输出省了 193 个 token** —— 而且结果直接可用。把要求写清楚，通常**总成本更低**。
2. **要求写得越具体，模型越听话**：说"300 字以内"它真的会守着；说"用 Markdown 小标题"它真的会分节。

### 5.3 课堂练习（改一个字看变化）

## 6. 代码编写报错原因以及解决办法

| 报错信息（关键词） | 原因 | 解决办法 |
| --- | --- | --- |
| `UnicodeEncodeError: 'gbk' codec can't encode character '\u2b50'` | **模型回复里带了 emoji（⭐）**，Windows 控制台是 GBK 编码，print 打不出来。本机 2026-10-12 真实踩到，程序直接崩 | 脚本开头加 `sys.stdout.reconfigure(errors="replace")`（打不出的字符变 `?`）；或终端执行 `chcp 65001` |
| `NameError: name 'prompt' is not defined` | `prompt` 变量没定义、或拼写不一致（如 `Prompt` / `prmopt`） | 检查变量名大小写与拼写 |
| `SyntaxError: invalid character '，'` / `'“'` | 用了**中文标点**：中文逗号、中文引号、中文括号 | 代码里的标点全部换成英文半角 |
| `BadRequestError` / 400 + `role` 相关提示 | `role` 写错（如 `"User"`、`"AI"`、`"system "` 带空格） | 只能是 `system` / `user` / `assistant`，全小写 |
| `BadRequestError` + `content` 相关提示 | `content` 为空字符串，或值不是字符串（漏了引号变成变量） | 检查 `"content": prompt` 的引号与变量名 |
| `messages` 顺序不对导致答非所问 | 把规则写在 `user` 里、或用 `assistant` 开头 | 规范顺序：`system` → 历史对话 → 最新 `user` |
| 回复内容是空的 | 思考模式吃光了 `max_tokens`（没传 `max_tokens` 时不会出现） | 见 day01 笔记 5.5 |
| `UnicodeEncodeError: 'ascii' codec ...` | 密钥里含中文（`.env` 写错，或系统里有同名环境变量） | 见 day01 笔记第 6 节；先 `echo $env:DEEPSEEK_API_KEY` |
| `ModuleNotFoundError: No module named 'zhipuai'` | 直接抄老师的智谱版代码，但本机没装智谱的包 | 本课用 DeepSeek：`from openai import OpenAI`，依赖只有 `openai` + `python-dotenv` |

## 9. 一句话小结 & 下节预告

**prompt = 你发给模型的那句话；写法决定质量。规则用 `system`，问题用 `user`，模型的历史回答才是 `assistant`。**

下一节方向：把单次问答变成**多轮对话** —— 自己维护 `messages` 列表，把每次问答追加进去，模型就能"记住上文"，做一个控制台聊天机器人。
